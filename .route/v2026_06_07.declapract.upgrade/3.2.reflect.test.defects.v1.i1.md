### classification: practice bug

### analysis

the upgrade introduced code that uses ES2022 `Error.cause` without update to tsconfig lib. declapract-typescript-ehmpathy should ensure tsconfig.json lib includes es2022 when code uses es2022 features.

### citation

the typescript practice extends base configs:
- `src/practices/typescript/best-practice/tsconfig.json` extends `@tsconfig/strictest` and `@tsconfig/node20`

the lib option comes from these base configs. however, if code in declapract-typescript-ehmpathy uses ES2022 features like `Error.cause`, the practice should ensure lib includes es2022.

### action

file issue or PR in ehmpathy/declapract-typescript-ehmpathy to update tsconfig practice to include es2022 in lib array.

## defect 3: node_modules cycles (superseded)

### classification: adoption candidate

### analysis

the original fix excluded node_modules from dpdm scan. this was a workaround, not a solution.

**better solution discovered**: scan `dist/` instead of `src/`

typescript erases `import type` statements at compile time. when dpdm scans dist/*.js:
- type-only imports are gone
- only runtime cycles detected
- no excludes needed
- devDependency cycles (e.g., @smithy/core) no longer appear

### the pattern

1. change test:lint:cycles to scan `dist/**/*.js` instead of `src/**/*.ts`
2. add failfast check for empty dist/
3. ensure CI builds before lint
4. remove all entries from .dpdmrc.yaml exclude list

### action

promote to ehmpathy/declapract-typescript-ehmpathy:
- update test:lint:cycles practice to scan dist/
- update .github/workflows/.test.yml to build before lint
- update .dpdmrc.yaml practice to empty exclude list
- see handoff document: `.behavior/v2026_06_10.fix-decycle/handoff.promote-dpdm-dist-scan.md`
